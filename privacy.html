D-deskcal 개인정보처리방침

최종 수정: 2026년 8월 14일

이 문서는 바탕화면 달력 위젯 D-deskcal(이하 "이 프로그램")이 이용자의 정보를 어떻게 다루는지 설명합니다.

1. 정보는 이용자의 컴퓨터에 저장됩니다

구글에서 받아 온 일정과 할 일은 이용자의 컴퓨터에만 저장되며, 개발자에게 전송되거나 개발자가 보관하지 않습니다. 제3자에게 제공하거나 판매하지 않습니다.

구글 로그인 표(토큰) %AppData%\DDeskCal\tokens
윈도우 계정 키로 잠가서(DPAPI) 저장합니다. 다른 계정으로는 열 수 없습니다.
일정 · 할 일 · 설정 · 메모 %LocalAppData%\DCWidget
calendar.db, settings.json, memos.json, todos-local.json 등

2. 구글 계정에서 청하는 권한

아래 네 가지만 청하며, 각각 다음 기능에 쓰입니다.

.../auth/calendar
구글 캘린더		 달력에 일정을 보여 주고, 이 프로그램에서 만들거나 고치거나 지운 일정을 구글에 반영하기 위해 필요합니다.
.../auth/tasks
구글 할 일		 할 일 목록을 보여 주고, 이 프로그램에서 더하거나 고치거나 완료 표시한 항목을 구글에 반영하기 위해 필요합니다.
.../auth/userinfo.email
openid		 설정 화면에 "어느 계정으로 로그인했는지"를 보여 주기 위해서만 씁니다.

로그인하지 않고도 이 프로그램을 쓸 수 있습니다. 그때는 일정과 할 일이 이 컴퓨터에만 저장되고 구글과 아무것도 주고받지 않습니다.

3. 외부와 통신하는 경우

이 프로그램이 인터넷을 쓰는 경우는 다음이 전부입니다.

3-1. 구글 캘린더 · 구글 할 일

이용자가 로그인한 경우, 일정과 할 일을 읽고 쓰기 위해 구글 API 와 통신합니다.

3-2. AI 일정 입력 (선택 기능)

"AI 일정 추가" 기능을 쓰면 그때 이용자가 적어 넣은 글이 구글 Gemini (generativelanguage.googleapis.com) 로 전송됩니다. 글에서 날짜와 제목을 뽑아내기 위해서입니다.

캘린더의 일정이나 할 일 목록이 함께 전송되지는 않습니다. 이 기능을 쓰지 않으면 아무것도 전송되지 않습니다.

3-3. 개발자가 운영하는 중계 서버

AI 기능에 쓸 공용 API 키를 내려받기 위해, 개발자가 운영하는 중계 서버(Google Apps Script)와 통신합니다. 프로그램을 켤 때 한 번, 그리고 AI 기능을 쓸 때 접속합니다.

이때 전송되는 것은 프로그램 버전, 요청 종류, 시각, 임의의 난수와 서명값뿐입니다. 이용자의 이메일 주소, 구글 계정 정보, 일정, 할 일, 메모, 적어 넣은 글은 전송되지 않습니다. 설정에서 개인 API 키를 넣으면 이 중계 서버를 쓰지 않습니다.

3-4. 업데이트 확인

새 판이 나왔는지 확인하기 위해 GitHub(api.github.com)에 접속합니다. 이때 개인 정보는 전송되지 않습니다.

4. 저장된 정보를 지우는 방법

  • 로그아웃 — 설정 창에서 구글 연결을 끊으면 로그인 표와 이 컴퓨터에 저장해 둔 구글 일정·할 일이 함께 지워집니다.
  • 전체 지우기 — 설정 창에 이 컴퓨터에 저장된 모든 자료를 지우는 기능이 있습니다.
  • 구글 쪽에서 권한 해제 — 구글 계정 권한 관리에서 이 프로그램의 접근 권한을 언제든 해제할 수 있습니다.

이 프로그램은 구글 API 로 받은 정보를 Google API Services User Data Policy(제한적 사용 요건 포함)에 따라 다룹니다.

5. 정보를 지키기 위한 조치

이 프로그램은 구글 캘린더의 일정과 구글 할 일을 민감한 정보로 보고 다음과 같이 보호합니다.

전송 중 암호화 구글 캘린더 · 구글 할 일 · Gemini · 중계 서버 · 업데이트 확인을 포함해 이 프로그램이 맺는 모든 연결은 HTTPS(TLS 1.2 이상)로 암호화됩니다. 암호화되지 않은 연결은 쓰지 않습니다.
저장 시 암호화 구글 로그인 표(OAuth 액세스 · 리프레시 토큰)는 윈도우 DPAPI로 암호화해 저장합니다. 이 암호는 그 컴퓨터의 그 윈도우 계정에 묶여 있어서, 파일을 그대로 복사해 가더라도 다른 계정이나 다른 컴퓨터에서는 열 수 없습니다.
접근 통제 일정과 할 일은 개발자의 서버에 전혀 저장되지 않으므로 개발자를 포함해 누구도 열람할 수 없습니다. 이용자의 컴퓨터에 저장된 파일은 윈도우 사용자 프로필 안에 있어 해당 윈도우 계정의 권한으로만 읽을 수 있습니다.
최소 권한 2절에 적은 권한만 청하며, 기능에 필요하지 않은 권한은 청하지 않습니다. 구글에서 받아 온 정보는 화면에 보여 주고 이용자가 고친 것을 구글에 되돌려 보내는 데에만 씁니다. 광고 · 이용 분석 · 인공지능 모델 학습에는 쓰지 않습니다.
보관과 파기 구글에서 받아 온 자료는 화면에 빨리 띄우기 위한 사본일 뿐입니다. 로그아웃하면 로그인 표와 함께 즉시 지워집니다(4절 참고). 개발자 쪽에는 보관본이 없으므로 따로 지울 것이 없습니다.
프로그램의 무결성 설치본과 업데이트는 GitHub 릴리스에서만 HTTPS 로 배포합니다. 자동 업데이트로 내려받은 꾸러미는 배포 목록에 적힌 SHA-256 해시값과 대조해 중간에 바뀌지 않았는지 확인한 뒤에만 적용합니다.
문제가 생겼을 때 개인정보와 관련한 문제를 발견하시면 아래 주소로 알려 주십시오. 확인하는 대로 조치하고, 이용자에게 영향이 있는 일이면 이 문서와 릴리스 안내를 통해 알리겠습니다.

Privacy Policy (English)

Last updated: 14 August 2026

D-deskcal is a desktop calendar widget for Windows. This policy explains how it handles user data.

Data stays on the user's computer

Calendar events and tasks retrieved from Google are stored only on the user's own computer. They are never transmitted to, or stored by, the developer, and are never sold or shared with third parties. OAuth tokens are stored encrypted with the Windows account key (DPAPI) under %AppData%\DDeskCal\tokens; other data is stored under %LocalAppData%\DCWidget.

Scopes requested and why

.../auth/calendar To display the user's events and to create, edit and delete events on their behalf.
.../auth/tasks To display the user's tasks and to add, edit and complete them on their behalf.
.../auth/userinfo.email, openid Only to show which account is currently signed in.

Signing in is optional; the app is fully usable offline with local-only data.

Network connections

  • Google Calendar and Google Tasks APIs — when the user is signed in.
  • Google Gemini (generativelanguage.googleapis.com) — the optional AI entry feature sends the text the user types into it, in order to extract a date and a title. Calendar events and tasks are not included. Nothing is sent unless the feature is used.
  • A relay operated by the developer (Google Apps Script) — contacted on startup and when the AI feature is used, to obtain a shared API key. Only the application version, the request type, a timestamp, a nonce and a signature are transmitted. No email address, account information, events, tasks, notes or typed text are sent. Users who enter their own API key are not routed through it.
  • GitHub (api.github.com) — to check for application updates. No personal data is transmitted.

Deleting stored data

Signing out removes the stored token and the locally cached Google data. The settings window also offers erasing everything stored on the computer. Access can be revoked at any time at Google Account permissions.

How we protect your data

D-deskcal treats Google Calendar events and Google Tasks as sensitive user data and protects them with the following mechanisms.

Encryption in transit Every connection the application makes — Google Calendar, Google Tasks, Gemini, the developer's relay and the update check — uses HTTPS (TLS 1.2 or higher). No unencrypted connection is used.
Encryption at rest OAuth access and refresh tokens are stored encrypted with the Windows Data Protection API (DPAPI), keyed to the user's Windows account on that machine. Copying the token file to another account or another computer does not make it readable.
Access controls Events and tasks are never stored on any server operated by the developer, so no one — including the developer — can access them. Files kept on the user's computer live inside the Windows user profile and are readable only under that Windows account.
Least privilege Only the scopes listed above are requested, and no scope is requested that a shipped feature does not use. Data received from Google APIs is used solely to display the user's schedule and to write the user's own edits back to Google — never for advertising, analytics or training AI models.
Retention and deletion Data received from Google is only a local cache for fast display. Signing out deletes it immediately together with the stored token. There is no developer-side copy to delete.
Integrity of the application Installers and updates are distributed only through GitHub Releases over HTTPS. Update packages downloaded automatically are verified against the SHA-256 hash published in the release manifest before they are applied.
Incident handling Privacy or security concerns can be reported to the address below. Reports are acted on as soon as they are confirmed, and any issue affecting users is announced in this document and in the release notes.

Limited Use

D-deskcal's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.
